# Key Files

Where to look for what. Paths relative to the repo root.

## Backend

| File | What lives there |
|---|---|
| `app.py` | Every Flask route (media serving, listing/probe, upload, projects, export settings, trim/splice/hold/reverse/render_timeline, chat/execute, `/api/version`). `CLAUDE_BIN` constant. The version group sits with the config constants at the top: `VERSION_FILE` → `_read_version()` → `APP_VERSION`, read once at import from the root `VERSION` file (falls back to `"unknown"` rather than refusing to boot — a missing version file must not take the app down), served by the one-line `api_version` route, and named in `app.run(extra_files=[VERSION_FILE])` so the dev reloader restarts on a bump. | `ffmpeg_utils.py` | Imported as `fu`. `FFMPEG`/`FFPROBE` paths, `INPUT_DIR`/`OUTPUT_DIR`, `ALLOWED_EXTENSIONS`, `safe_path`, `get_video_info`, `encode_args` + `EXPORT_QUALITIES` + `MULTIPASS_QUALITIES`, the custom-export block (`EXPORT_CODECS`/`EXPORT_PRESETS`/`EXPORT_PROFILES`/`EXPORT_PIX_FMTS`/`TEN_BIT_*`, `DEFAULT_EXPORT_SETTINGS`, `_EXPORT_SETTING_BOUNDS`, `_EXTRA_ARG_CONFLICTS`, `normalize_export_settings`, `validate_extra_encode_args`, `custom_target_bitrate_kbps`, `render_custom_two_pass` — which deliberately MIRRORS `render_size_capped` rather than generalizing it, so the two hand-verified `under50mb*` modes stay untouched; | `frontend/src/clipMath.js` | `clipSpeed`/`clipMainSec`/`clipTotalSec`/pixel math, `roundUpAmount` (+`ROUND_EPSILON`), `sanitizeHoldPlacement` (hold placement invariant), `nextSplitName`, `duplicateNames` (the `_a`/`_b` pair naming — returns the original's new name too, so `DuplicateButton` renames the source clip in the same state update as the insert and one undo covers both), `clipColor`/`CLIP_PALETTE` (literal Tailwind classes), `clampNoiseGainDb` (stepper text → a number the server will accept; mirrors `app.py::_a1_noise_gain_db`, and returns a parsed 0 AS 0). Also the **V1 lane geometry** any other lane has to align to: `MIN_CLIP_PX`/`clipRenderedPx` (the 24px floor `TimelineClip` draws), `sequencePosToPx` (timeline seconds → X inside a lane laid out with V1's per-clip widths + 2px flex gaps), `sequenceClipBounds` (per-clip left/width + head/tail hold spans) and `sequenceVideoStartSec` (where V1's picture starts — clip 0's head hold; mirrors `bed_offset_sec` in the render). `AudioBedBar` measures every edge with these — see the gotchas entry on why `sequenceSec * pps` is the wrong width. And the **A1 lane's own pure math**, node-testable like the rest: `normalizeBeds`/`bedLaneEndSec` (positions, clamped forward so a gap is never negative) plus the split group — `bedInSec`/`bedOutSec`/`bedPlayedSec` (a clip's window into its file and the lane length that follows from it; every reader of a clip's length goes through `bedPlayedSec`, never `durationSec`, or a split half draws and plays at its file's full length), `bedFileTimeAt` (lane seconds → file seconds), `canSplitBed` and `splitBed` (the whole edit — see the **A1 split** glossary entry), and `moveBed(beds, index, startSec)` — the whole A1 move: it writes ONE clip's `startSec` and no other's, snaps to the nearest position the clip fits in (two clips can't overlap, so a drag against a neighbour lands flush and closes a hole exactly), returns `{beds, index}` with the lane re-sorted by start (both `normalizeBeds` and the server read the lane in ARRAY order) and the same array reference for a move that changes nothing or has nowhere to go, so `reduceEdit` bails and no undo step is spent. `bedSwapTarget(beds, index, dir)`/`swapBeds(beds, index, dir)` are a **different** A1 edit, and the one the toolbar's `Move ◀ ▶` and `⌥←`/`⌥→` perform: the selected clip **trades places with its neighbour** — the counterpart of `moveClip`'s reorder on V1, and the only A1 edit that moves a clip other than the selected one. The pair keeps the span it already occupied: the neighbour takes the selected clip's start, and the selected clip lands so it ends where the neighbour ended, with the gap that was between them still between them. Holding both outer edges is why this needs no `fits` test and no `bedGeometry` at all — the two clips cover the same stretch of lane as before, so a swap can never collide with a third clip or run off the head of the lane whatever the durations are, and pressing the other way is an exact undo. `bedSwapTarget` returns the neighbour's index or null (first clip going earlier, last clip going later), which is exactly the button's disabled state — the same rule V1 uses. `swapBeds` returns `{beds, index}` like `moveBed`, same array reference when there's no neighbour, and the index matters for the same reason (the two clips exchange array slots, and identity on A1 is position). And the **V2 fuse group** (see the *fused clip* glossary entry): `fuseGroups(clips)` — the lane order partitioned into runs the user sees as ONE clip each, `{fuseId, start, clips}` per run, derived fresh on every read from a shared `fuseId` plus adjacency and, **for a reconstructed run only**, agreement on `reversed`/`speed`/`crop` (a merged run carries `fuseMerged` and skips that check; so a stale id is inert and nothing has to sanitize it) — and `fuseGroupIds(clips, id)` (the set of ids that must die together on delete). `mergeClips(clips, ids)` is Merge's whole decision: it validates the pick (≥2, all present, a CONSECUTIVE run — adjacency is the ONLY requirement, a retime or reverse on one member is fine), then either collapses the run into one clip (same source, ranges adjoining in play order — `a.outSec==b.inSec` forward, `a.inSec==b.outSec` reversed — one speed, one direction, identical crop, no `cropKeyframes`, no interior hold) or stamps a shared new `fuseId` **+ `fuseMerged: true`** on the members, which exempts the run from `fuseGroups`' agreement rule so a mixed retime still draws and renders as one. Returns `{error}` with a sentence fit to show, or `{clips, selectId, collapsed}` — one function for both the disabled state and the edit. Every V2 clip COUNT goes through `fuseGroups`; safe on V1, which has no `fuseId`s. And the **move (reorder) group**, shared by all four move surfaces: `moveClip(clips, from, to)` (clamps, and returns the SAME reference for a no-op so `reduceEdit` bails), `dropTargetIndex(from, overIndex, side)` (the drawn insertion boundary → a destination index, including the `from < to` correction) and `clipStartSec(clips, id)` (cumulative timeline start, so the playhead can follow a moved clip). And the **footage-loss measure** behind the V1 warning: `trimLossSec(clip, newIn, newOut)` — deliberately SIGNED, so one edge drag's stream of pointermove reports sums to the NET change — and `deleteLossSec(clip)`. Both in **source** seconds, never `clipMainSec`'s speed-stretched timeline seconds. And the **render's frame arithmetic**, mirrored from `ffmpeg_utils.clip_timing` because the browser has to predict a render's cut points with no render in flight to ask: `roundFrames` (Python's half-to-**even** rounding — every rounding in the mirror goes through it, see the gotchas entry), `clipFps`, `holdFrames(sec, fps)` (a hold's real `round(H*fps)` length), `clipMainFrames` (the body's whole selected frames, `outSec` clamped to the stream's last frame, floor of 1), `clipRenderedMainSec` — `clipMainSec`'s frame-exact counterpart, and the one to use for anything that must line up with rendered footage — `sequenceTargetFps` (the render's one output rate, `max` clip fps), `clipRenderFrames(clip, {isFirst, isLast, targetFps})` (**the single implementation** of a clip's frame budget and its head/main/tail/round split, which `analyzeMath.sequencePieces`, `sequenceRenderFrames` and the round-up warnings in `App.logMessages` all build on — there is deliberately no helper that answers "how long does this clip render to" from a clip ALONE, because the answer depends on the clip's POSITION: the render zeroes any hold that isn't at the sequence's outer edge and quantizes onto the sequence's output grid, not the clip's own) and `sequenceRaise` (what Raise offers: the frame-exact base plus the smallest hold whose render reaches the next whole second, with `exact: false` when none lands on it). The JS and Python copies must change together; see the gotchas entry. |

Two load-bearing choices: it **reuses** anything already listening on 5001/5173 rather than killing it (a killed Flask orphans a render into `output/.partials/`; an existing Vite is usually the user's own session), and it spawns windows with `open -a Terminal <wrapper>` rather than `osascript … do script`, because AppleScript into Terminal is an AppleEvent needing Automation permission and dies `-1712` without it (measured). The wrapper is a two-line throwaway in `$TMPDIR/genai-editor-launch/` named for the window title, and exists only because `open -a` cannot pass arguments. Also carries the 5174 fallback, since `strictPort` is unset in `vite.config.js`. Duplicates the **run-app** skill's job for humans; keep the two in step. |
