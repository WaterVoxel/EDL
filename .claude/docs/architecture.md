# Architecture

GenAI Editor is a local, macOS-only, EDL-style video editor: a Flask JSON API backend driving ffmpeg, plus a React 19 + Vite 8 + Tailwind 4 frontend. Every edit (trim, splice, duplicate, reverse, speed, holds, round-up) is staged as plain data on clip objects in React state; nothing touches media on disk until the user clicks Render, which POSTs the clip list to `/api/render_timeline` for a **single-pass ffmpeg render**. Source files in `input/` are never modified.

## Backend (2 files, no database, no async queue)

- **`app.py`** (~800 lines) — all Flask routes, grouped by `# ---------- name ----------` banner comments:
  - Media serving: `GET /input/<name>`, `/output/<name>` (raw), `/preview/<which>/<name>` (browser-playable transcode via `.preview_cache/`, keyed by basename+mtime).
  - Listing/probing: `/api/files`, `/api/outputs`, `/api/probe/<name>?dir=input|output`.
  - Upload/clear: `/api/upload` (2 GB cap), `/api/clear_input`, `/api/clear_output`, plus their single-file counterparts behind each bin's right-click Delete — `DELETE /api/files/<name>` (input/) and `DELETE /api/outputs/<name>` (the export dir, so it follows an `output_dir` override).
  - Project library: `/api/projects` CRUD — saves `.nara` JSON files into `projects/`.
  - Export settings: `/api/export_settings` GET/POST persisted in `.export_settings.json` — `output_dir`, `quality`, plus the `"custom"` quality mode's own encode settings (`custom`) and the named settings bundles (`presets`). **POST is a partial update**: it only touches keys present in the body, because two different dialogs write to it (the Export Bin's ⚙ owns `output_dir`, the top bar's gear owns `custom`/`presets`) and either one posting the whole document would wipe the other's field. GET additionally returns `custom_defaults` + `custom_options` (the allowed codecs/presets/profiles-per-codec/pixel formats), which is where the gear dialog's dropdowns come from — the UI never hardcodes a list the validator might reject. `/api/browse_directory` (osascript folder picker), `/api/reveal_file` (`open -R` Finder reveal) — both macOS-only. `reveal_file` and `/api/rename_file` take an optional `dir` (`"input"` → `fu.INPUT_DIR`, default `"output"` → `get_output_dir()`, via `resolve_media_dir`) so the same two routes serve the Media Bin's and Export Bin's right-click menus.
  - Editing ops: `/api/trim`, `/api/splice`, `/api/hold_frame`, `/api/reverse` (2 GiB RAM warning + confirm flow), and the main one, `/api/render_timeline` (timeout 1800s).
  - A1 stem: `/api/render_a1` — the A1 Render button. Same request shape as `/api/render_timeline` (it takes the payload `clipsToPayload` already built) but reads only each clip's timing keys, renders `fu.build_a1_filter` to a **`pcm_s16le` .wav** (a stem to mix elsewhere, so never the lossy export-quality codec), and opens **no clip as an ffmpeg input** — the clips are probed for fps/`video_duration` and nothing else, so no video is decoded.
  - Chatbot: `/api/chat` shells out to the `claude` CLI headlessly (JSON schema, session resume via `-r`); `/api/execute` runs a user-approved command after `validate_ffmpeg_command` gates it.
  - Runs `app.run(host="127.0.0.1", port=5001, debug=True)` — localhost-only by design.
- **`ffmpeg_utils.py`** (~500 lines, always imported as `fu`) — all ffmpeg machinery: hardcoded binary paths, `safe_path` traversal guard, `get_video_info` probe, `encode_args` quality modes, the two-pass size-capped renders (`render_size_capped` for both `under50mb*` modes, `render_custom_two_pass` for the user-configured `custom` mode, `MULTIPASS_QUALITIES` naming the three that need two ffmpeg invocations instead of an `encode_args` list), the settings validator behind the gear dialog (`normalize_export_settings` + `validate_extra_encode_args`), the filter-graph builders (`build_timeline_filter`, `build_concat_filter`, `build_holdframe_filter`), `run_ffmpeg` (prepends binary + `-y`; args must NOT include `ffmpeg`), `unique_output_name`, `validate_ffmpeg_command`.
- `requirements.txt` is literally one word: `Flask`. Python 3.9.6 venv at `.venv/`.

## Frontend (`frontend/src/`)

- **`App.jsx`** (~520 lines) — top-level state owner: file lists, **all three timeline tracks via one `useUndoableTracks({v1, v2, a1})` call** (one shared undo history — `timelineClips`/`track2Clips`/`audioBeds` are named slices of a single state object, so Cmd/Ctrl+Z steps back the last edit on *any* lane; `reset` replaces all three with no history for project-open and `handleCleared`), `selectedId` + `selectedPart`, V2's own `selectedId2`/`selectedPart2`, `focusedTrack` (which track the shared toolbar row and Delete key act on — lifted here from Timeline.jsx), `selectedBedIndex` (which A1 clip **Split alone** acts on — A1 is deliberately not a `focusedTrack` value, so an audio selection never takes the rest of the toolbar or the Delete key off the video clip; picking a video clip clears it, so Split always cuts whatever was clicked last) and `laneClockRef` (a function Timeline assigns during render returning the playhead in A1 **lane** seconds — a ref, not state, because lifting the ~15 Hz position here would re-render the app every frame during playback), `centerTab` (`'timeline'|'assistant'|'actions'`, which pane of the center-column dock is visible), `v1Visible`/`v2Visible` (the per-track eye toggles, also lifted out of Timeline.jsx so the preview stage's overlay layers honor them), `v2RenderMode` (`'A'|'AB'` — what the V2 Render button outputs; session-only, not persisted in `.nara`), `v2ShotMode` (`'1'|'1+'` — whether that button writes one file or one per cut; session-only for the same reason) and `v2ShotProgress` (`{done,total}` while a 1+ series is running, which is what makes the button count the shots off), render/analyze/save/export handlers, panel widths, and two mirrors of backend export state (`exportPresets`, which `buildProject` writes into the `.nara` file, and `exportQuality`, which lights the top bar's gear while the `custom` mode is active — both fetched once on mount and updated by the gear dialog's `onSettingsChange`). It derives both overlay sets here too — `overlays` (plain `matchOverlays`, drives the live preview) and `abOverlays` (`{ fullFrameSameSize: true }`, used only when rendering in A/B mode). The toolbar row (Trim/Hold/Reverse/Speed/Crop/Duplicate/Splice/Raise) is passed `activeClips`/`setActiveClips`/`activeSelectedClip`/`setActiveSelectedId` — derived from `focusedTrack` — instead of hardcoded V1 values, so the same components edit whichever track is focused.

### Three-column layout

- **Left** — mirrors the right column's own shape exactly: source preview video, then always-visible Media Info In, then the Media Bin as a `flex-1` card — its file list fills the same remaining column height Export Bin's own list does (`MediaLibrary.jsx` has the identical video/info-slot/flex-1-bin structure `OutputPanel.jsx` does; App.jsx passes `TechInfoPanel` into `MediaLibrary` as `children` so the info panel sits between the two, matching the right column's Media Info Out placement).
- **Center** — Preview stage (its header carries `FrameGrabButtons` on the left, where the "Preview" label used to be, and `CropForm` on the right), then the Timeline's transport/render bar, then a tabbed dock (`centerTab`) holding Timeline / AGENT (ChatPanel) / Actions (LogPanel) — only one visible at a time. The two horizontal bars here are **crossed on purpose**: the row above the dock is an empty slot div that `Timeline.jsx` `createPortal`s its own action bar (transport clock, V2 Reconstruct/V2 Analyzer/V2 Batch Analyzer, V1 Render/V2/A1) into, while the clip edit toolbar App.jsx builds (`editToolbar`: Undo ↩ + Hold/Trim/Duplicate/Reverse/Split/Raise/Speed + A1 Room Tone + its dB stepper) is passed *down* as the `toolbar` node and drawn as the Timeline card's first row. Each half stays owned by whichever component holds its state — the action bar needs Timeline's `useTimelinePlayback` transport, the tools need App's `focusedTrack` derivation — so only DOM position moves, not logic. Both halves therefore live inside the tab-gated pane's lifetime: they're present only while Timeline is the active dock tab. Timeline is `centerTab`'s default; switching to AGENT/Actions hides the Timeline entirely (not just visually — it unmounts) and the dock grows to fill the column's remaining height instead of Timeline's own fixed content height.
- **Right** — preview video, Media Info Out, then the Export Bin as a `flex-1` card (`OutputPanel.jsx`) — the layout the left column now mirrors.

Both AGENT's and Actions' panes carry `data-tour="agentDock"` (a legacy id both share, since one guided-tour step describes the dock as a whole) — `App.jsx` switches `centerTab` mid-render when the tour reaches a step targeting a tab-gated element, so `TourOverlay` never tries to spotlight something hidden behind an inactive tab. `renderBar` (the portal slot) is in that list for a subtler reason than the rest: its element is *always* mounted, so the overlay would find it and spotlight an empty strip — the gate is about the bar's contents, not the target's existence.
- **`api.js`** — thin fetch wrappers over every backend endpoint, relative paths (Vite proxy handles routing; no CORS anywhere).
- **Pure logic modules** (deliberately extracted for node-testability): `clipMath.js` (durations, pixels, `sanitizeHoldPlacement`, `nextSplitName`, `CLIP_PALETTE`), `analyzeMath.js` (`analyzeAgainstV1`, `batchCutAgainstV1` + `sequencePieces`/`sequenceCutOffsets`, `reconstructFromV1`), `cropAnimation.js` (keyframe interpolation/retiming), `overlayMatch.js` (`matchOverlays` — which V2 clips composite onto V1), `exportPresets.js` (export-settings form conversion, preset identity/merge, the codec↔profile↔pixel-format coherence rules, bitrate preview), `timecode.js`, `fileList.js` (localStorage favorites/sort/filter).
- **Hooks**: `useTimelinePlayback.js` (rAF scrub-loop playback engine + transport API), `useUndoableTracks.js` (the one undo stack shared by V1/V2/A1; exports the pure `reduceEdit`/`reduceUndo` for node-level unit tests, plus `nextGesture` for drag coalescing).
- **`context/MediaContext.jsx`** — shares ONE `videoRef` + `currentTime` + `activePreview` across MediaLibrary, PreviewPlayer, Timeline, and SpliceButton.
- **`components/Timeline/`** — Timeline.jsx (lanes, gutter, keyboard, drag-reorder, V2 buttons + the two switches beside V2 Render: A / A/B for what it outputs, 1 / 1+ for how many files), TimelineClip.jsx (head/main/tail/round segments, edge-drag trim), TransportBar.jsx, Playhead.jsx, Ruler.jsx, EdlTable.jsx.
- **`components/`** — toolbar forms (HoldFrameForm, TrimForm, ReverseForm, SpeedForm, RaiseButton, SpliceButton, DuplicateButton), panels (MediaLibrary, OutputPanel, TechInfoPanel, LogPanel, ChatPanel), dialogs (RenderDialog, ProjectLibrary, ExportSettings, FfmpegCustomSettings, AboutDialog), utilities (Dropzone, PreviewPlayer, FrameGrabButtons, OverlayPreview, DownloadButton, NumericStepper, ClearButton, SortFilterBar, ContextMenu).

## Dev topology

Two servers, always: Flask on `127.0.0.1:5001`, Vite dev server on `127.0.0.1:5173` proxying `/api`, `/input`, `/output`, `/preview` to Flask (see `frontend/vite.config.js`). The React UI 404s on every fetch if Flask isn't running. `frontend/dist/` exists from past builds but **nothing serves it** — dev mode is the only supported way to run the React UI.

## Legacy UI

`templates/index.html` + `static/app.js` (~490 lines vanilla JS) is served by Flask at `http://127.0.0.1:5001/` — a functional but feature-frozen fallback (upload, trim, splice, hold, reverse with the old two-click confirm, chat). It has none of the newer features (timeline render, projects, export settings, speed, raise, split, V2). Don't add features to it.

## Render pipeline (the heart of the app)

`/api/render_timeline` → per-clip validation → `fu.build_timeline_filter(clip_specs, ...)` builds one `filter_complex` string: per clip, optional **overlay composite** (a V2 region placed back on the raw frame at animated keyframe coordinates) → optional `crop` (also keyframe-animatable) → `split` if that filter-produced source feeds more than one chain → optional lead freeze (trim one frame + loop) → trimmed main segment (with `reverse`/`areverse` and/or `setpts` speed stretch) → optional trail freeze → concat pieces → normalize to max resolution/fps across inputs (scale/pad/setsar/fps + hard frame cap) → concat all clips into `[outv][outa]` → one `run_ffmpeg` call with `encode_args(combined_info, get_export_quality())`.

The tail of that is the one place the quality mode changes the *shape* of the render rather than just its flags: for the three modes in `fu.MULTIPASS_QUALITIES` (`under50mb`, `under50mb_hevc`, `custom`) there is no single args list, so all six render routes hand the same `input_args`/`filter_args`/`info` to `app.multipass_export_render` instead, which dispatches to `fu.render_size_capped` (the two fixed 50MB modes) or `fu.render_custom_two_pass` (the gear dialog's settings) and raises `RuntimeError` on failure so each route's existing `except RuntimeError` still reports it.

The terminal has **three** mutually exclusive forms, and `[outa]` is the contract every one of them honors (so `-map "[outa]"` never changes): with `no_audio=True` it concats `a=0` and emits `[outv]` only (there is no `[outa]` to map, and `-an` is *not* a substitute — it fails with "Cannot decode a disabled input stream"); with no bed it concats straight to `[outv][outa]`; with an **A1 audio bed** or **room tone** (or both) it concats to `[outv][aseq]` and sums the layers with `amix=inputs=N:duration=first:dropout_transition=0:normalize=0[outa]` — `[aseq]` FIRST (it is the length authority), then `[abed]` built from the A1 lane's inputs (several A1 clips are butt-joined by a single `concat`, with any HOLE between them interleaved into that same `concat` as an `anullsrc` piece — never a per-bed `adelay`, which would grow `amix` by one input per clip and make the mixed level depend on how many clips A1 holds; the width stays 3 for 1/2/3 clips. Gap pieces are pinned by sample count — `anullsrc`'s `duration=` floors, `atrim=end_sample` is exact — and their `aformat` precedes that `atrim` because `concat` negotiates format from its FIRST input, which a gap piece becomes as soon as clip 0 is the one removed. A **split** A1 clip rides in the same `concat` as an `atrim=start_sample:end_sample` on the clip's own input — one per `bed_trims` entry, `aformat` first again, here so both halves are cuts of the *same* resampled stream and the two joined are bit-identical to the uncut clip) (`aformat` → `apad=whole_dur=N` → `atrim=end=N` → `asetpts` → `volume=BED_GAIN`), then the room-tone label from `noise_track()` (a per-clip concat of `noise_slice()` runs, bounded to each clip's `expected_sec`, each scaled by `volume=<noise_gain_db>dB` — the request's `noiseGainDb`, defaulting to `NOISE_GAIN_DB`). The bed is appended before the tone so a bed-only render still emits the exact two-input mix it always did. The tone input is emitted **only if `noise_fill_plan()` found silence to fill**, so a fully-covered timeline produces a graph byte-identical to the toggle-off one. `no_audio` + a bed is structurally impossible and raises `ValueError` → 400. Four facts here are measured, not assumed: `normalize=0` is an **exact unity-gain sum** (max error 3.7e-09 at two inputs, 3.73e-09 at three), so V1's dialogue keeps its level; `duration=first` both pads a short bed and cuts a long one; `aformat` must precede `apad` or resampling shifts the tail 14 samples; and `aresample=async=1` must **never** be added, since it can insert/drop samples and would make renders non-deterministic. `N` is `sum(expected_secs)` — the frame-quantized per-clip truth, which diverges from wall-clock duration by up to 0.076 s under mixed fps + slow-mo. Adding a bed changes **no video frame hash** (verified: 105 frames, identical hash across no-bed/short/long/exact).

### The A1 stem render (`build_a1_filter`)

`/api/render_a1` renders the A1 track **alone** to a `.wav` that is exactly as long as the equivalent V1 render, so it drops into another tool already in sync. It is deliberately built out of the V1 graph's own parts rather than a parallel implementation: `fu.clip_timing(spec)` — extracted from `build_timeline_filter` and now the single source of truth for `(lead_frames, trail_frames, expected_sec)` — supplies the length (`head = clip 0's lead_frames/fps`, `total = sum(expected_sec)`), and the bed chain is reproduced node for node (`adelay=delays=<ms>:all=1` → `aformat` → `apad=whole_dur=N` → `atrim=end=N` → `asetpts` → `volume=BED_GAIN`), then summed with the silence skeleton by the same `amix=...:duration=first:dropout_transition=0:normalize=0`. The skeleton is built **per clip** (not as one `anullsrc` of `N`) so it quantizes exactly the way the V1 graph's `[aseq]` does, and it carries no sound of its own — it is there for the LENGTH. Room tone, when on, runs the same `noise_fill_plan()`/`noise_track()` against the same clip list, so the stem places tone in exactly the stretches the V1 render fills — which is why each clip's `has_audio` is load-bearing here even though no clip audio is rendered. Room tone with no bed and nothing to fill raises `ValueError` → 400 rather than writing a silent file. **No clip is an ffmpeg input** — the clips are probed for fps/`video_duration`, then only the bed and the noise asset are opened, which is why an A1 render costs about a second on a timeline that takes minutes to render as video. Verified against the equivalent V1 render: identical sample count (3.500000 s single-clip; 7.000000 s on a 3-clip mixed-fps timeline with a reversal, a 0.5× slow-down, a 0.51 s head hold and a tail+round hold), and by subtraction — `((V1+A1+tone) − V1plain) − A1stem` leaves **3.73e-09** on a timeline carrying clip audio, holds at both ends, a silent source and a slow-motion clip, with all three passes at exactly **286,650** sample-frames, well under one float32 LSB. The one measured imperfection is **pre-existing and unrelated to room tone**: where per-clip frame counts are odd, the half-sample roundings accumulate and the stem can come out a sample or two **shorter** than the render's audio (measured 536549 vs 536551 on a 12.1667 s three-clip timeline, identically with the toggle off and on) — ≈45 µs, not an alignment error, and the tone track changes no length either way.

Holds keep audio and video aligned through the **order of the concat pieces, not any explicit delay**: a lead freeze prepends `[vlead{i}]` to the video pieces and an `anullsrc` of the same length to the audio pieces, so the clip's own dialogue is pushed later by exactly the hold. That makes the silence's length load-bearing — it is quantized to `lead_frames / fps` (the freeze's own frame count), never the raw `lead_hold_sec`, because a hold that isn't a frame multiple would otherwise run the audio late against the picture *and* lose the overflow off the tail to the per-clip `atrim`. Each A1 clip's own position is a lane-relative `startSec` (0 = V1's picture start, *excluding* the head hold), which is why removing one leaves a gap instead of pulling the rest up, and why a head-hold edit never has to rewrite it. The A1 lane follows the hold rule only at the **head**: it is delayed by the first clip's head hold (`bed_offset_sec`, the same `lead_frames / fps`) so it starts where V1's *picture* starts instead of over the frozen frame, and remove or resize that hold and the bed moves with it. Past the head it is `apad`-ed flat across the rest of the sequence and never sees a per-clip transform, so it stays **timeline-locked** — it plays straight through mid-sequence holds, reverse, and slow-mo rather than being offset again. The head delay uses `adelay=delays=<ms>:all=1`, which *prepends silence* rather than shifting PTS: the downstream `apad=whole_dur=N`/`atrim=end=N` therefore still measure from 0, so a 1 s hold means 1 s of leading silence and 1 s less bed heard, never a render that runs 1 s long. (`all=1` is required — without it `adelay` only shifts the channels it was given delays for, so a stereo bed comes out with one channel early.) The frontend mirrors all of it: `AudioBedPlayer` slaves to `transport.getTimelinePos()` minus that same start offset, plus the clip's own `inSec` (parking paused at `inSec` whenever the playhead is outside the clip's own stretch, the head hold included), and `AudioBedBar` measures its geometry with `clipMath.sequencePosToPx` and starts at `sequenceVideoStartSec` so the bar sits under V1's actual pixels.

Two ordering facts are load-bearing. **Overlay comes before crop**: cropping first would throw away the very pixels the overlay is composited back onto. **Both come before trim/reverse/speed**, so their keyframe `t` is always *source* time — one `keyframe_ladder` (module-level in `ffmpeg_utils.py`) generates the piecewise-linear `if(lt(t,…))` expression for both filters, and holds/reverse/slow-mo/concat then inherit correct behavior with no overlay-specific handling anywhere downstream. Each overlay gets its own `-i` even when two clips use the same file, since a filter graph can't consume one input pad twice. Overlays deliberately do **not** influence the render's target resolution (`effective_wh`) — the frame size is V1's.

There is exactly one way to reach a composite render: **V2 Render with its toggle on A/B**. `handleRenderV2Click` branches on `v2RenderMode` — `A` renders the V2 track alone as before, `AB` renders V1 with `abOverlays` attached (`clipsToPayload` nulls the overlaid V1 clips' `crop`/`cropKeyframes` and hangs an `overlay` object off each spec). Nothing else in the app produces `overlay` specs; the live `OverlayPreview` layers are purely visual.

**Shot-by-shot renders (the 1 / 1+ switch) are a frontend loop, not a backend feature.** `handleRenderConfirm` branches on `v2ShotMode` for the two V2 targets only (V1 Render never splits) and hands off to `App.renderShots`, which POSTs `/api/render_timeline` once per clip — a single-clip payload each time, output names from `renderNames.shotOutputNames(baseName, n)`, sequentially so one pass finishes before the next starts. The backend is untouched: every shot is the ordinary single-clip render it already did, which is what makes a 1+ series frame-identical to the 1 render laid end to end. The consequences of the split all fall out of the per-render derivations in `render_timeline` — `target_w/h/fps` are now that one clip's, the size-capped budget is per file — plus two frontend decisions: the A1 lane is not sent (it is timed to the V1 *sequence*) and mid-sequence holds are zeroed to match the server's own first/last rule (see gotchas.md).

The **return leg** of a `1`-mode render is `analyzeMath.batchCutAgainstV1` (the **V2 Batch Analyzer** button) — also pure frontend, and also bound to that same first/last hold rule, since it has to reproduce where the cuts landed in a file the render already wrote. It splits V2's single joined clip at V1's cumulative durations, which is a *different time base* from `analyzeAgainstV1`'s (that one copies V1's source IN/OUT points). What it cuts at are the sequence's **pieces** (`sequencePieces`), not its clips — the edge holds are stretches of the joined file in their own right, so each comes back as its own V2 clip. Nothing about the render pipeline is involved: it rewrites clip objects, exactly like Analyze and Reconstruct.
